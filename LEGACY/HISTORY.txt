# HISTÓRICO DO PROJETO - MONERO REMOTO

Este arquivo contém o registro cronológico das atualizações, decisões técnicas e refatorações realizadas no projeto.

## [Data: 08/01/2026] - Refatoração para Windows Service e Limpeza

### 1. Análise Inicial
- O projeto foi identificado como um sistema de gerenciamento remoto para mineração (XMRig) via TCP.
- Estrutura original continha dependências pesadas como Chocolatey (`ProjetoCHOCO-INTERFACE`).

### 2. Mudanças de Arquitetura
- **Remoção do Chocolatey**: A pasta `ProjetoCHOCO-INTERFACE` foi excluída. Decidiu-se que a instalação de pacotes via Chocolatey era "ruidosa" e desnecessária, já que o agente Python tem privilégios de administrador para realizar tarefas diretamente.
- **Python vs Node.js**: Confirmada a escolha do **Python** como tecnologia base para o agente (Client Side) devido ao acesso nativo à Win32 API e capacidade de gerar executáveis compactos (`.exe` simples vs Runtime V8 pesado do Node).

### 3. Implementação de Windows Service
- O script principal `SystemOutCache.py` foi completamente refatorado.
- **Antes**: Script Python simples que abria janelas e dependia de sessão de usuário.
- **Agora**: Serviço Nativo do Windows (`win32serviceutil`).
    - Roda em Session 0 (invisível/headless).
    - Inicia automaticamente com o Windows (StartType=Auto).
    - Possui "Keep-Alive": Se o socket cair, o serviço reinicia a conexão em 5 segundos.
    - Autodetecta o diretório de trabalho correto (evita rodar no `System32`).

### 4. Automação e Build
- **Instalação**: Criado script `install_service.ps1`.
    - Verifica privilégios de Admin.
    - Cria regras de Firewall (Porta TCP 7722).
    - Instala e inicia o serviço automaticamente.
- **Compilação**: Criado `BUILD_INSTRUCTIONS.md` e gerado o binário `SystemOutCache.exe` usando PyInstaller (`--noconsole --onefile`).

### 5. Documentação
- **README.md**: Criada documentação profissional detalhando Tech Stack, Instalação e Uso.

---
**Status Atual**: O sistema está pronto para deploy como um EXE único, instalável via script PowerShell, rodando de forma furtiva e resiliente como serviço do sistema.
